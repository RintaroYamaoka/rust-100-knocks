# 2026-08-30 — ヘッダーの進捗表示が常に「0 / 0 問クリア」で固まっていた

## 何が起きたか

スマホ最適化のためにヘッダーを実機幅で見ていたところ、進捗が
**「0 / 0 問クリア」から一切動かない**ことに気づいた。一覧には 100 問並び、
問題を解けばバッジは ✓ に変わるのに、ヘッダーの数字だけが初期値のまま。

この表示は 2026-08-25 の初回デプロイから壊れており、本番でもずっと 0 / 0 だった。
テストは全部緑。DOM も正しく存在する (テキストが更新されないだけ)。

## 原因

Leptos の購読が張られていなかった。壊れていた式:

```rust
{move || format!("{} / {}", passed_in_level.get(), problems.with(|p| p.len()))}
```

`passed_in_level` は `problems` を材料にする `Memo`。この表示クロージャが最初に
実行されたとき、まだ未計算の `passed_in_level` を **先に** 読んだため、その初回計算
(= 内側の観測者) の中で `problems` が読まれる。そのあと外側で `problems.with(...)`
を読んでも購読が張られず、`problems` が到着してもこのクロージャは二度と再実行されない。

`passed_in_level` 自体は 0 のままなので (未正解なら値が変わらない)、そちらの経路でも
再実行は起きない。結果として「初期値で固まる」。

ブラウザで同じ式を別の span に足すと **そちらは正しく更新される** (Memo が計算済みに
なった後の初読みなので購読が張られる)。この非対称さが、原因を分かりにくくしていた。

## 直し方

材料 (= 素のシグナル / 先に確定する Memo) を **先に** 読む:

```rust
{move || {
    let total = problems.with(|p| p.len());   // 先に読む = 購読を張る
    format!("{} / {}", passed_in_level.get(), total)
}}
```

`crates/app/src/app.rs` のヘッダー進捗表示。実測で 0 / 100 → 正解すると 1 / 100 に
更新されることを確認した (iPhone 13 エミュレーション + 実 API)。

## なぜ検証をすり抜けたか

- **host テストの射程外**。`crates/app` の純ロジック (集計関数) は正しく、
  壊れていたのは「シグナルの購読が張られたか」という描画時の性質だけ
- **ブラウザ検証が要素の存在で止まっていた**。`.header-progress` は存在し、
  文字列も入っている。「データ到着の前後で値が変わる」ことを見ていなかった
- 一覧・バッジ・進捗率バーは別経路で正しく動くので、画面全体としては正常に見えた

## 再発防止

- CLAUDE.md の「既知の地雷」に **Memo と材料の読み順** を追加した
- ブラウザ検証では、非同期データの **到着前と到着後で値が変わること** を
  1 つ以上のアサーションで見る (存在確認で止めない)
